# Evaluation of Source Code Summarization Models

This report evaluates the quality of source code summaries generated by two models: `codellama:7b-instruct` and `deepseek-coder:6.7b`. The summaries are evaluated based on accuracy, completeness, and clarity. The summary files have been renamed to replace colons with underscores for cross-platform compatibility.

## Source Code Files

The following files were used for testing:
1. `source_code/complex_logic.cpp` (Order processing simulation)
2. `source_code/graph_algo.cpp` (Dijkstra's algorithm)
3. `source_code/matrix_utils.c` (Matrix operations)

## Comparison

### 1. `complex_logic.cpp` - `processOrders`

**Code Functionality:**
The function processes a batch of orders. It logs progress, skips non-PENDING orders, checks inventory (and logs missing items), reserves stock, calculates subtotal, applies discounts (quantity, priority, seasonal), calculates tax (based on region), finalizes the order (deducts stock, updates status), and returns a summary string.

**CodeLlama Summary:**
- Identifies the main steps: validate inventory, reserve stock, calculate subtotal, apply discounts, calculate tax, finalize order, log summary.
- Mentions specific logic like "skips the order" if items are not available.
- Correctly identifies "deducting" reserved stock.
- **Pros:** detailed step-by-step breakdown.
- **Cons:** None significant.

**DeepSeek-Coder Summary:**
- Summarizes the high-level logic: updates status, inventory availability, customer priority, seasonal discounts, tax rates.
- Mentions tracking processed count, failed count, and revenue.
- **Pros:** Concise high-level overview.
- **Cons:** Less detailed about the specific control flow (e.g., skipping orders).

### 2. `graph_algo.cpp` - `dijkstraShortestPath`

**Code Functionality:**
Implements Dijkstra's algorithm using a priority queue. Takes a graph (adjacency list) and source node. Returns a vector of distances. Handles `INF` initialization.

**CodeLlama Summary:**
- Correctly identifies Dijkstra's algorithm.
- Mentions priority queue usage.
- Explains the return value (vector of distances).
- **Pros:** Accurate technical details.

**DeepSeek-Coder Summary:**
- Correctly identifies Dijkstra's algorithm.
- Mentions finding shortest paths from source to all other vertices.
- **Pros:** clear and concise.

### 3. `graph_algo.cpp` - `reconstructPath`

**Code Functionality:**
Reconstructs the path from source to target by backtracking from the target using the distance array. It iterates neighbors to find the predecessor.

**CodeLlama Summary:**
- States it uses Dijkstra's algorithm to compute shortest distance (incorrect - it *uses* the result of Dijkstra, doesn't compute it again).
- Says it reconstructs the shortest path.
- **Cons:** Misleadingly implies it computes distances again or uses Dijkstra itself, whereas it takes `dist` as input.

**DeepSeek-Coder Summary:**
- States it reconstructs the shortest path using Dijkstra's algorithm *given the distances*.
- **Pros:** More accurate wording regarding the input (`dist`).

### 6. Anomalies

- **`Order._clinit_`**: Both models hallucinated or inferred a function `Order._clinit_`. This does not exist in the C++ code. It likely comes from how the models parse struct initialization or generated bytecode/intermediate representation if they were trained on such data, or they simply hallucinated a Java-like static initializer for the `Order` struct.
- **`log_void_std.string__`**: The function name in the summary includes the signature. This suggests the input to the models might have been the function signature or a mangled name, or the models formatted the output this way.

## Conclusion

Both models provided accurate summaries for the provided C/C++ code.

- **CodeLlama** tends to provide more step-by-step, algorithmic descriptions, which is useful for understanding *how* the code works.
- **DeepSeek-Coder** provides slightly more concise, high-level descriptions, which is useful for understanding *what* the code does.
- Both models struggled with `Order._clinit_`, indicating a potential issue with how structs are perceived or parsed, or a shared hallucination pattern.

Overall, **DeepSeek-Coder** felt slightly more natural in its language, while **CodeLlama** was more mechanical but very detailed.
